# 修改处理流程

## 修改触发场景

用户在以下环节可能提出修改：
1. 目录审核阶段（修改章节结构或知识点）
2. 章节内容审核阶段（修改 PPT 或课件内容）
3. 全部完成后的整体调整

## 修改处理原则

1. **精准定位**：明确用户要改的是哪个章节、哪个产物（PPT/课件）、哪个部分。
2. **最小改动**：只改用户指出的部分，不重写整个章节。
3. **保持一致**：修改 PPT 时检查课件是否需要同步修改，反之亦然。
4. **重新交付**：修改后必须重新通过 `present_files` 交付更新后的文件。
5. **说明变更**：交付时简要说明改了什么，方便用户核对。

## 目录修改流程

```
用户提出目录修改
  ├─ 理解修改意图（增/删/改/调序）
  ├─ 更新目录
  ├─ 重新编号（如涉及章节增删）
  ├─ 检查逻辑连贯性
  ├─ 输出完整目录
  └─ 等待用户确认
```

**注意**：目录修改后，如已有章节已生成，需告知用户哪些已生成章节会受影响。

## 内容修改流程

```
用户提出内容修改
  ├─ 定位：章节 N + PPT/课件 + 具体位置
  ├─ 判断修改类型
  │   ├─ 内容增删 → 修改对应 section
  │   ├─ 表述调整 → 改写对应文字
  │   ├─ 代码修正 → 修改代码块及注释
  │   ├─ 样式调整 → 修改内联 CSS
  │   └─ 结构调整 → 重新组织页面/章节
  ├─ 执行修改
  ├─ 同步检查（PPT↔课件一致性）
  ├─ 重新交付文件
  ├─ 说明修改内容
  └─ 等待用户确认
```

## 常见修改类型与处理方式

| 修改类型 | 示例 | 处理方式 |
|---------|------|---------|
| 增加内容 | "这页加一个对比表格" | 在对应位置插入表格，PPT 可能需新增一页 |
| 删除内容 | "这个知识点不用讲" | 删除对应 PPT 页和课件小节，更新页码 |
| 改写表述 | "这段讲得太复杂，通俗点" | 改写文字，保留核心含义 |
| 修正错误 | "这个公式写错了" | 修正公式，检查课件中推导过程是否需同步修正 |
| 调整顺序 | "这两页换一下" | 交换页面/小节顺序，更新导航和页码 |
| 样式调整 | "字体太小/颜色不对" | 修改内联 CSS 对应属性 |
| 增加案例 | "加一个实际例子" | 新增案例页/小节，确保与上下文衔接 |

## 多轮修改

- 同一章节可能经历多轮修改，每轮都按上述流程处理。
- 不要因为修改次数多而简化流程或跳过审核。
- 如果用户的修改要求相互矛盾（如先要求增加后要求删除），以最新要求为准，并简要确认。

## 修改记录

在对话中自然记录修改要点，不需要单独存文件。但在交付修改后的文件时，用简短列表说明：

```
本次修改：
- PPT 第5页：增加了 XX 与 YY 的对比表格
- 课件第2节：修正了公式推导中的符号错误
- 课件第3节：补充了代码注释
```

## 边界情况

- **用户要求大改**：如果修改范围超过该章的 50%，建议确认是否重新生成该章。
- **用户要求改已确认章节**：允许回溯修改，但需提醒用户这可能影响后续章节的衔接。
- **修改涉及目录变更**：回到目录修改流程，重新确认目录后再继续。
