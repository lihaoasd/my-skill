# 目录制定指南

## 目录结构模板

生成目录时严格按以下格式输出，便于用户审核和后续逐章生成：

```
## 课程目录

**课程名称**：{课程名称}
**目标受众**：{受众}
**预计章节**：{N} 章

---

### 第1章：{章节名称}
- 知识点1：{一句话描述}
- 知识点2：{一句话描述}
- 知识点3：{一句话描述}
- （预计 PPT：{X} 页 / 时长：{Y} 分钟）

### 第2章：{章节名称}
- 知识点1：...
- ...

---

**审核提示**：请检查章节逻辑是否连贯、知识点是否有遗漏或重复。确认后回复"确认"或提出修改意见。
```

## 目录设计原则

1. **逻辑递进**：章节按"基础→进阶→应用"或"问题→原理→实践"的顺序排列。
2. **粒度均匀**：每章知识点数量 3-8 个，避免某章过于臃肿或过于单薄。
3. **不重不漏**：相邻章节知识点不重叠；课程核心主题必须被覆盖。
4. **可教学性**：每个知识点应能在 1-3 页 PPT 内讲清，过大的知识点需拆分。
5. **受众匹配**：入门课程侧重概念与示例；进阶课程侧重原理与权衡；高级课程侧重工程实践与前沿。

## 常见课程类型的目录参考

### 技术类课程（如"Python 数据分析入门"）
- 第1章：环境搭建与基础语法
- 第2章：数据结构与文件读写
- 第3章：NumPy 数值计算
- 第4章：Pandas 数据处理
- 第5章：数据可视化
- 第6章：综合案例

### 概念类课程（如"机器学习基础"）
- 第1章：机器学习概述与分类
- 第2章：线性回归与损失函数
- 第3章：逻辑回归与分类评估
- 第4章：决策树与随机森林
- 第5章：模型评估与调优
- 第6章：实战项目

### 实操类课程（如"Docker 容器化部署"）
- 第1章：容器技术概述
- 第2章：Docker 安装与镜像管理
- 第3章：容器操作与数据卷
- 第4章：Dockerfile 编写
- 第5章：Docker Compose 编排
- 第6章：生产环境部署实践

## 目录修改处理

用户提出修改时，按以下方式响应：

| 用户反馈类型 | 处理方式 |
|-------------|---------|
| 增加章节 | 在合适位置插入新章节，重新编号 |
| 删除章节 | 删除后重新编号，检查后续章节逻辑 |
| 合并章节 | 合并知识点，标注合并原因 |
| 拆分章节 | 将大章节拆为两章，重新编号 |
| 调整知识点 | 增删改对应章节下的知识点 |
| 调整顺序 | 重新排列章节，确保逻辑连贯 |

修改后必须重新输出完整目录（不只是修改部分），方便用户整体审核。
